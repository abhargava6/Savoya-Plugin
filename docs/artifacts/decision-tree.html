Savoya quoting — decision tree

Every node resolves to one of four outcomes. Anything not listed is skipped. Nodes A–J are quote-intake; K–Q are quote-document. The handoff folder is the seam between them.

A

Client · resolve_client

skipname is in known_clients → use the cached profile id callotherwise. One hit → proceed and cache it askseveral profiles, or none. Never guess
A client Savoya does not have gets a stand-in (R102). The user names an existing client with no discount on its company and none on its profile. The quote runs under it, and handoff.py write --client-source stand-in --prospect "<real name>" refuses if the quote carries any contracted discount. The document says "Prepared for" the real name, and the delivery reminder says to book under the real client. When it asks about a client or a stop, it adds one tip: start with "Use savoya plugin to quote" and put the client ID and full street addresses in the request (R101).
A resolved client is still mandatory on every path. There is no rack-rate or no-client route — not in the plugin, not in the MCP, and not in Core's in-progress work either. That is PRD R9, the oldest unaddressed gap in the product, and PRD R4 (a standalone client-facing rate sheet) sits behind it.

B

Passenger · resolve_passengers

skipunless the user named a passenger. That is the whole rule callthey named one → match the name, send that id askseveral matches (batched with A and D)
passenger_id is optional on every pricing tool. Omitted, Core deterministically attaches an eligible passenger to the unsaved calculation and says so in a warning.
No cache, no pre-flight check. The old rule — take the first result and cache it per profile — was correct against the previous contract and verified then (two passenger ids, byte-identical quotes). Caching now would only keep alive a disclosure the CSM no longer needs. A profile with no eligible passengers isn't ours to pre-empt: we don't look, so we can't know in advance. Core raises it, the plugin surfaces it.

C

Vehicle types · resolve_vehicle_types

callonce per quote, every quote. Core owns id, capacity, classification, greeter, bus, limited_availability and client_can_book
This reverses an earlier decision. A static table existed to save a per-quote call, and the trade stopped being worth it the moment the table was found wrong rather than merely stale: it said Exec Van "~10" where Core says 14, and omitted seven types including both greeters. One call against a wrong answer is not a saving.
vehicle-types.md stays for what Core has no concept of: physical dimensions and terminology. Since 0.27.5 the dimensions are internal screening only (R35): a figure is never stated to a client, a session asks the user for any dimension a constraint needs, and the answer is recorded as a supplied fact. client_can_book: false (Mini Bus, Coach Bus) is a field to read, not a rule to remember — and it is read here rather than from the rate sheet, which omits it even though Core knows it in the same payload (ENGINEERING.md G2, PRD R70).

D

Stops · resolve_itinerary_stops — one call, every leg, deduplicated

firstdecide stop_type: hotel/venue/street → address; airport code or flight intent → airport; "around the city" → as_directed, never as a pickup skipone candidate, or several that are the same place — same id and address → take the first, note it askgenuinely different places, or nothing resolved
Both halves of that match matter. "Anaheim Convention Center" returned three candidates all under id: 4645260 — the venue at 800 W Katella, a Residence Inn at 640, a Hampton Inn at 100. Matching on id alone would have quoted a hotel instead of the venue.
Airports: use the IATA code. "John Wayne Airport, Santa Ana, California" resolved to nothing; SNA resolved first time. Colloquial names fail. As-directed city: query "<City>, <State spelled out>" — abbreviations return nothing (ENGINEERING.md C1) — and pick the candidate whose id matches the pickup's city.
Every stop lookup is recorded, and an unresolved one stops the flow (R83). Pass each to handoff.py write as --stop-note "<stop>|<query sent>|resolved" (or unresolved). If an as-directed stop does not resolve, ask the user for an address. Never substitute another stop — a session once priced a hotel round trip in place of an unresolved Whistler tour — and never delete a travel time to get past verify. write refuses an unresolved note.
Every airport stop carries a flight object, pickup or drop-off: arrival when it's the pickup, departure when it's the drop-off, always commercial_tbd: true. Omitting it fails the call, and stops[0] on an arrival leg is where it gets missed. A missing flight time is a recorded placeholder — don't ask, it doesn't change the price.
TBD is the only shape we send, deliberately. The contract also describes known-commercial flights (needs airline as a resolved object) and private ones (needs fbo), and neither resolver exists in the contract. Even when the client gives a flight number, keep it as a client-facing note and still send commercial_tbd: true. PRD R14 and R52; ENGINEERING.md B7 and B7b.
A stop can sit in no Savoya service area at all. A live London/Sicily/Milan itinerary resolved with Sicily in no market, which Core handles by reporting one market as both source and primary and pricing from Naples — 14.75 hrs billed against a shorter request. It is not an error, and it has to be disclosed to the client in generic wording, since there is no second market to name. It also broke the sourcing feature's own verifier, which read that equality as a contradiction.

E

Questions · one per message, wait after each

ask 0Blocking gaps — missing year or ambiguous date, headcount range, unresolvable location, unsettled service shape. Batched with D's stop ambiguities ask 1Rate sheet first, or straight to the quote? FYI on the question (R103): an extra discount is not stored in Savoya, so the booking prices without it unless it is added to the client's profile. ask 2Best value · options · you name the vehicles
1 and 2 are asked on every quote, never skipped because the request looks self-evident. Client questions that don't change pricing (tax, gratuity, cancellation, on-site staff) are recorded with --client-question for the document stage — don't ask, don't block. "go" means no rate sheet, best value.
A headcount range is never priced on a default (R84). "50–75 passengers" means ask which number to quote, as question 0 and before pricing. The chosen number is passed to pricing and to handoff.py write --headcount N. The same request priced with no number defaulted every leg to one 50-seat coach.
State the reading of every named scenario and get a yes before pricing (R81). One line each: vehicles and counts, hours, headcount. The same request was once priced two ways about $7,000 apart. After the yes, each reading is recorded with --reading and travels into the document's assumptions.
Nothing about discount, commission, cover, personalization, maps or formats is asked here. All of it belongs to the document flow.

A later "show me the rate sheet" just calls it then; stop refs live roughly 24 hours (ENGINEERING.md C2 — measured, not specified). Covers capacity-bearing vehicles only — greeters never appear here, and are not listed in missing_vehicle_type_ids either, so the rate sheet is silently incomplete rather than wrong (PRD R24).

F2

Nearby markets · lookup_nearby_markets — when the primary market is short

always firstan inventory check before every exact quote, even when E said no rate sheet: run the preview with display: "internal" and compare the requested vehicle count against the returned market count. No count stated → derive it from passenger count and the returned capacity skipthe primary market covers the request → quote there and skip this node entirely callshort, or the CSM explicitly asks to explore — with reference_service_area_id and inventory_date. Returns the three nearest markets by road distance, each with the vehicle types and quantities it adds, plus a signed market_ref optionalresolve_service_areas first, to anchor the lookup to a market the CSM names rather than the itinerary's own askpresent the table, then stop. The CSM names the market or mix, the vehicle type and the quantity for each
This is an inventory check, not a driver or vendor schedule check — the counts are static fleet numbers, not date-specific availability. PRD R48–R49; user-initiated this phase, so the plugin never goes shopping on its own.
A sourced vehicle bills the primary market's rates, not its home market's. Confirmed live: an Austin Mini Bus sourced into Dallas billed Dallas's $314.92/hr, not Austin's $244.09/hr. The nearby market supplies the vehicle, not the price. A nearby market's own rate sheet can be shown and a CSM may legitimately want it — but lead with that fact, and when a sourced quote is in play name both numbers.
The counts are "additional", not totals. Vehicles whose vendors already serve the reference market are excluded, because they are already counted there. A CSM reading "Market B · SUV 4" will otherwise promise a client four SUVs that may not be four extra ones. They are also unconfirmed and promise nothing about fulfilment — say both when presenting the table.
A market_ref is scoped to the market it was looked up from, and nearby is not the same as sourceable: Dallas returned only Shreveport, Austin and Oklahoma City while Houston sits in Austin's list. To source into Dallas, look up from Dallas. On sourcing_reference_expired, look up again from the same reference market and swap each ref for the new one — don't ask the CSM again.
The CSM has the vehicles from a vendor (R95). Ask how many, which vendor and who confirmed. Price the largest quantity Core accepts, ingest it, then run handoff.py extend-quantity, which changes the quantity and the totals that follow and nothing else. Never multiply a unit by hand. The extension is internal, never in a client document, and goes away when Core allows the quantity (ENGINEERING.md H5).
A lookup is not a choice, and never consent. Never pick a source market for the user, and never read a lookup or a rate preview as agreement to source. And never compare an unpriced option: a session did rate-sheet arithmetic and told a CSM sourcing from Austin would save about $80; the real quote came back $707.18 more expensive, because the arithmetic had missed the positioning drive time that sourcing exists to pay for.

Never quote the primary portion alone and present it as the full package. A mixed-market package is one call and one Core-returned aggregate total.
A temporary rate is a BASE rate — the client's discount comes off it. Verified 8 Oct: $250.00/hr supplied became $192.50/hr effective after a 30% contracted discount and 10% fuel. So when asking, say so: "this is a base rate before the client's contracted discount — give me the rate you want to quote from, not the cost you were quoted." A CSM who enters the partner's cost quotes the client 23% below it. This is the one place it can be caught; afterwards it just looks like a price.
No stored rate in the market is never an estimate and never a dead end — there is no approximate path to fall back to. Core's own recovery wording is the flow: ask for a temporary rate, or pick another vehicle, then re-quote. A waiting leg can only take an hourly temporary rate — a transfer rate needs exactly two stops, and our ≲3h out-and-back rule produces three routinely (verified 7 Oct: quote_units_unavailable).
Every option must contain every trip. Core rejects a duplicate outright — "labels alone do not create an alternative." An option that drops a leg is a cheaper total for a different job. strategy is a label, not a lever: the same two options run twice with only the strategy strings swapped returned identical totals, vehicles, quantities and rate ids. The vehicle argument is the only thing that selects.
Split the headcount across vehicle groups (R91). 75 passengers on a coach plus two vans is 50 on the coach and 25 on the vans, each priced with its own passenger_count. Core sizes the number of vehicles from a group's count, so 75 on every group prices extra vehicles. handoff.py write refuses a unit with no count, and groups serving one trip whose counts do not add up to the confirmed headcount.
Every pricing response is saved by a checked step, and packages become options (R78, R79). handoff.py ingest --name A checks that the units add up to Core's total and never edits the response. A generate_quote_options response goes through the same step: each option is checked and saved as its own package, and alternatives pair with the Option A unit that has the same key. Separately priced packages (one coach all day, or two coaches for four hours) are written together with --package A --package B and become options in one document, each keeping Core's own total, with no combined figure.
Send requested_stop_count on every unit — the user's own total including pickup, dropoff and every intermediate. It exists so Core can tell it was handed fewer stops than were asked for; silently dropping a stop is the bug class that produced 0-minute drive times in 0.20.0.
Hours are Core's. duration is the lever, not the answer: an as-directed stop sent duration: 4 bills 5.25 hours — a constant +1.25 h of positioning. Out of market it is larger: duration: 8 billed 12. Send what the user asked for, show what Core billed, name the difference. Never back-solve the duration.
A client's time has a kind (R18, R34). Classify it as flight departure, pickup or airport arrival target; wording decides, and the user is asked only when it does not. For a departure or a target, price at the target, read travel_times, set pickup = target minus drive time (a departure first loses the 2 h domestic or 3 h international lead), and re-price once at that pickup. write --time-reading accepts a priced pickup that puts the car at the airport 0 to 10 minutes before the target (R105); still outside after one re-price, the user confirms the pickup. The document prints both times.
Overlaps and held-open stops (R97, R98). An hourly block that runs across a same-day airport transfer is one question: start the block after the transfer, at the client's time, or another time. It is recorded with --overlap and asked within one option only. Vehicles on the same date, time and stops are one trip in parallel and are never asked about (R107). A stop the user is holding open prices at its resolved location and prints a neutral label such as "Plano, TX (pickup address to be confirmed)" (--placeholder-stop).
What the client supplied is printed as supplied (R74, R62, R35). A supplied flight (--flight) prints as given and is never a placeholder; a venue the client named (--venue) keeps that name; a dimension Core does not return is asked of the user (--fact). The fuel surcharge is whole-quote only: header and terms, never a leg, a note or an email line.

G3

Greeter / on-site staff · a Core quote unit, never a number a human invents

Greeters are vehicle types: 12 Hourly Greeter/Coordinator, 13 Single Greet. Both return greeter: true, capacity: null.
Always check the rate first. An Irvine quote carried a hand-entered "On-site coordinator — 4 hrs at $235/hr = $940" against Core's $404.20 for the same request. 2.3× over, in front of a client. The rule it produced: never ask a human for a number Core has.
callthe rate check is an attempted price, not a lookup. Greeters are absent from preview_rate_batch and aren't in missing_vehicle_type_ids either — the rate sheet cannot answer. So price one: a priced unit means the market has a rate, status: "blocked" means it doesn't

The rate check is the constant; the location follows who raised it. What the client asked for is part of the quote they requested. What the CSM adds is an add-on to a finished quote.
The unit shape is pickup + an as_directed stop carrying the hours. A duration on the dropoff is ignored and the unit collapses to the 2-hour minimum. One per message. The script decides what's next, so none is skipped, merged or reordered — and it also drops questions: cover and map aren't asked for an email-only job, because nothing but the PDF and printable document reads those answers. The format is asked first (R110), so this holds even when the user never named one. Pricing questions come before presentation ones, which is why commission sits where it does rather than at the end.
The commission amount is computed in code, never by the session (R59, R82). The rate is recorded with apply_adjustments.py --commission-pct. The amount is the subtotal after every discount and before the fuel surcharge, times the rate, per option, rounded half-up. It changes no total, never enters the adjustment lines, and is the most prominent figure after the option total in the PDF and the email. No beneficiary is named, because the commission may be the client's or an agency's. On No, nothing is recorded and the word appears nowhere.
The discount rule reversed in 0.23. This node used to say never re-quote through the engine, which was right under the old contract and is wrong now: a discount applied here was our arithmetic on Core's number, while a discount applied through Core is Core's number — it returns the whole standard → discount → net line with nothing left to compute. Discounts are additive in basis points: 30% contracted + 10% here = 4000, not 37%. Never persisted.
There is no fuel question (7 Oct). Fuel is market-scoped and engine-applied; nothing in the contract subtracts it, and temporary_discount is additive rather than a way to remove a surcharge. A CSM who needs it waived does that in Savoya and the quote is rebuilt. The [if:fuel_surcharge] terms bullet stays, because it reflects what Core actually applied. SKILL.md went on contradicting this for three days — telling sessions to add fuel as a document percentage line, which is refused outright — and a session following it hits a hard refusal mid-money-handling and then improvises.

Adjust · apply_adjustments.py

callflat document lines apply in order on the running total refusea document percentage line is refused outright — percentages are Savoya's to compute neverremove an engine-sourced line (contracted discount, fuel, special handling). They survive --clear and can only be waived callthe commission rate is recorded here — this script owns the terms block, so the rate and its bullet land in one call and cannot get out of order
And the total fails closed. If the engine's share of the document total no longer equals Core's aggregate_total, the render refuses and names that share explicitly. The old code absorbed the gap into the last engine line, which made the document reconcile and made that line misstate its own percentage — it put a 5-vehicle Boston job 30 cents above Savoya's own quote. Engine line amounts are pinned to Core's granularity (per hour, per vehicle) with the fuel line as the remainder, so standard + lines equals Core's aggregate by construction.
A document line moves what that check compares; it does not switch it off. The check originally ran only when no document line had been added — true of the total, not of the engine's share of it. One flat $200 coordinator line disabled the only fail-closed money check in the plugin, on a quote also built from a hand-transcribed engine response. Reproduced: a $100 slip in one leg's line total ships a client document $100 light, silently. A waived engine amount is added back before comparing, too — Core's aggregate still contains it, and until that was fixed --waive refused on every waiver and was unusable.
Every discount gets its own line — and a reconciling total does not prove it. The contracted discount comes from discount_basis_points; an additional one from temporary_discount_basis_points, under Core's own temporary_discount_label. Reading only the contracted field left the extra discount inside Core's net with no line, so the fuel remainder swallowed it and printed −$422.39 as a "Fuel surcharge" at a stated +10% on a real client quote. The total was right the whole time — which is exactly why nothing failed. Fuel is now the remainder of all discounts, and a guard checks each line's sign against its own stated percentage.
Option B's total is Core's amounts summed, never percentages re-applied. It compounded two discounts — 30% then 5% gives 0.665 where Core's additive 35% gives 0.65 — and came out about 2.3% high on a live quote, overstating the cheaper option and understating the saving being offered. It survived because Core never prices an Option B combination as a package, so there was nothing to check it against: the only total nobody could verify was the only one still doing its own arithmetic.

What the flow asks about, the flow writes. decide.py recorded the personalization answer and nothing carried it into quote.json, so two of three live sessions hand-edited the document to set the event name and intro note — and one of those hand-written notes asserted that tax and driver gratuity were included, contradicting the terms on the final page of the same PDF. A rejected note is a wrong note.
Read only the one format reference you need. A degraded output is never shipped as if fine: no basemap means the offline overview or no map, never a blank panel. Email headings carry day, clock time, route and headcount — the same four facts the PDF line has always had; before that every heading in one live draft was rewritten by hand before sending, and a heading a CSM has to retype is one that can be retyped wrong.
A schematic map is a different claim from a street map. The map needs three public services — OSM tiles, the OSRM demo router, Nominatim at 1 req/s — and corporate networks block them routinely. Below 60% tile coverage the map is redrawn from coordinates the engine already resolved: stops in true relative position, joined in order, on a near-white grid. CSMs reported that as "blank with just straight lines", which is a fair description of a picture nothing on the page explained. The document now titles them differently — Itinerary map versus Itinerary overview · stops in order — not a driving route — and the schematic states that its lines are not driving routes. Tell the CSM which one went out: they decide whether a schematic suits that client and can't see the PDF as the client will until it's sent.
Notes collapse and totals come first (R99). Line notes with identical text print once, naming their legs; notes of 70 characters or fewer print inline under the route; the totals block sits on the first summary page, not behind the notes.
A no-commission copy is a variant (R100). On request, no_commission_copy.py works on a copy, checks that no total moves, renders it under a separate file name and records both files. Keep the first for internal use.
Only the formats asked for (R85). A PDF-only job drafts no email; an email is offered in one line. verify_document.py prints the deliverables, and draft_email.py refuses a PDF-only job unless asked. When an email is asked for, two versions come: the full email and a short one that carries each option and leg total, the discount and the commission amount, and points to the PDF (R71). A client request that changes no price becomes one neutral "noted, will confirm" line (R73). The email asks for flight details only when a flight is outstanding (R74).

Capture · capture_session.py, once per conversation

callboth passes upload — a snapshot on the render pass and the full capture after the feedback exchange, under different titles callalways compressed (gzip+base64, declared in the envelope). There is no size at which a capture stays behind askthe upload failed because the connector is off, or lacks Editor on the folder → ask the user to switch it on and try again. Once, after the deliverable, never before it neversplit a capture across uploads onceconsent (R76) — the first document on a machine prints CAPTURE CONSENT UNASKED. Ask once, in plain words, with the name to file the record under. After a yes every upload is silent; after a no nothing is written or uploaded callverification writes the snapshot and leaves a pending-upload marker; the upload happens before the files are presented (R63) blockeda session that cannot produce a document still reports: capture_session.py --blocked (R80). The user can also say "log this session" at any point; the same record is saved (R90)
Upload the real file, exactly (R94). A blocked-session record was once uploaded as a condensed retyped copy, marked not durable. Each capture file now prints its byte count and SHA-256, the blocked record is uploaded packed like the full capture so it cannot be summarized, and the unpacker warns when a file does not match its hash.
It reads handoff/intake.json itself. Captures carry real client names, addresses and pricing — the folder is restricted.
~ is not the user's computer. On claude.ai the home directory is a cloud container reclaimed with the session; on a linked desktop the shell's home is an isolated VM. Only a connected folder is really the user's disk. Two real captures — 192 KB and 36 KB — were written to ~/.savoya-quoting/captures/, reported as saved, and lost. The report now states whether the local copy is durable and why not, and when it isn't, Drive is the only destination and the upload is not optional.
Three rules here each replaced a specific loss. The old rule kept any capture over 25 KB local, so the richest sessions were exactly the ones that never arrived — measured, gzip gives about 15× and base64 still leaves 17 KB. Holding the full capture until after the feedback exchange made the richest artifact depend on a conversational step, and on a live quote that step was skipped, so it reached the folder only because the user asked by name. And a failed upload used to mention rather than ask, which is how three sessions in a row ended with the record stranded — the user is the only one who can switch the connector on.
This is the only channel back to whoever maintains the plugin, and it cannot fail on you. --request is optional, a missing handoff is noted rather than fatal, an unexpected error still writes a failure record and exits 0, and a malformed call writes a refusal record — because the step is specified as silent, so argparse printing usage to stderr is a bug report that never happened. Telling the user about a bug is not reporting it; they are not the maintainer.
Capture hardest when the session went worst. A session that patched a renderer in a working copy or rebuilt a line by hand is the most valuable one of the week and the most likely to skip this while firefighting. That belongs in --workaround — and the highest-risk one found that way is the hand-transcribed engine response: five sessions re-typed a quote response too large to save, which defeats the fail-closed total check, because both sides of its comparison then come from the same typing. That is ENGINEERING.md G6.

Two installed copies is a silent fork. Every older upload stays on disk, which makes the un-suffixed directory permanently the first one ever installed — so a glob on the bare name matches it and nothing else. The skills themselves load from the current copy, so the flow looks right and the duplicate is invisible; but a session that located a script by name ran September's, whose capture_session.py has no --auto flag, so the call was rejected and the session recorded nothing. Both skills now match savoya-quoting* and take the highest version numerically — as strings, "0.9" sorts above "0.25", and this repo has passed through both — and the setup check names the shadowed lookup.
It exists because a CSM could finish setup, believe they were done, and quote for weeks with nothing reaching the folder and no symptom on either side. preflight.py never helped here: it checks local Python packages and never touches a connector, the folder, or identity.
