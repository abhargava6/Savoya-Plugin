# 0.23 — MCP contract migration

Analysis of *Savoya MCP to Plugin Integration Handoff* (September 2026) against
savoya-quoting **0.22.0**. Written before any code changed, on branch
`new-mcp-version-09-24`.

**Nothing in this document has been implemented.** It exists to be argued with.

---

## The shape of the change

The handoff moves the ownership boundary: the plugin keeps conversation, presentation
and export; the MCP and Core own every number. That is not a patch to the quoting path —
it removes the plugin's authority to compute money at all, and the plugin currently
computes money in two places that the document flow depends on.

Three consequences are larger than the handoff spells out. Each is flagged **▲** below.

---

## What has to change, with evidence

### 1. Removed tools are still wired in — 16 references across 10 files

`plan_approximate_quote_units` and `calculate_quote_options` are gone, with no fallback
estimate path. They are referenced in instructions *and in code*:

| File | What it does with them |
|---|---|
| `quote-intake/SKILL.md` | names `plan_approximate` as the documented fallback (Step 5) |
| `quote-intake/references/decision-tree.md` | node G routes to it when a profile has no passengers or a market has no rates |
| `quote-intake/scripts/handoff.py` | records it as a source tool |
| `quote-document/scripts/normalize_quote.py` | branches on approximate-shaped responses |
| `quote-document/RULES.md`, `evals/evals.json`, `handoff-contract.md`, `feedback-archive.md`, `assets/plugin-root/README.md` | encode it as expected behaviour |

**▲ Removing the fallback removes an outcome, not just a code path.** Today a profile with
no eligible passengers, or a market with no stored rate, still produces a labelled
estimate. Under the new contract that request is a dead end. The handoff says a
zero-passenger profile "still blocks exact quoting" but does not say what the CSM is
supposed to do instead. **This is a product decision and it needs an answer before we
build.** (Q1 below.)

### 2. `calculate_temporary_quote_units` is entirely new — 0 references today

Temporary rates and discounts currently never leave the plugin. This tool is the
replacement for all of it.

### 3. Passenger handling is backwards

`decision-tree.md` node B: *"take the **first result without asking**; cache it"* — with a
recorded justification that pricing is passenger-independent (two passenger ids,
byte-identical quotes). The new contract says omit `passenger_id` unless the user named
one, and keep `passenger_count` separate as group size.

The old behaviour was verified true at the time. It is now wrong by contract. Affects
`decision-tree.md`, `quote-intake/SKILL.md`, `handoff.py passenger`, and the cache file.

### 4. The static vehicle catalog becomes advisory

`quote-intake/references/vehicle-types.md` carries hardcoded ids and capacities
(`1` Sedan/3, `8` SUV/6, `26` Sprinter/13 …) and `SKILL.md` explicitly says *don't* call
`resolve_vehicle_types` unless a type is missing from the table — a context-budget
decision. Ids and capacities must now come from MCP/Core.

**▲ This reverses a deliberate optimisation.** The table exists because per-quote tool
calls were costing context and latency. Making `resolve_vehicle_types` authoritative adds
a call to every quote. (Q4 below.)

### 5. Local money math must go — and this is the biggest blast radius

Two scripts compute money today.

**`apply_adjustments.py`** is the whole document-level pricing layer: percentage and flat
adjustments compounded in list order (`recompute()`, lines 89–110), used for the discount
question, the fuel surcharge, the greeter fee, and waivers. The handoff puts
"locally compounded percentage adjustments" under *Do not use these as final* and the
release gate says *no plugin script calculates or compounds a final monetary total*. This
script is that script.

**`apply_adjustments.py` lines 117–125** absorb any penny-level difference between the
plugin's reconstruction and the engine total into the last engine-sourced line:

```python
residual = eng_total - quote["total_cents"]
if residual and abs(residual) <= max(50, len(quote["legs"]) * 10):
    eng_lines[-1]["amount_cents"] += residual
    quote["total_cents"] = eng_total
```

The handoff is explicit: *"If normalized data and the raw MCP result disagree, **fail
closed**. Do not repair the difference with arithmetic."* This code is exactly that
repair. It must become a hard failure.

**▲ Fail-closed will break documents that render today.** Any quote whose reconstruction
drifts by a cent currently renders fine and will start refusing to render. That is the
correct behaviour and it is also a visible regression for CSMs. It needs to be a
deliberate, announced change, not a surprise. (Q3 below.)

### 6. The document flow contradicts the new contract in writing

`quote-document/references/questions.md:15`, on the discount question:

> **Do not re-quote through the engine.** If the engine already applied a discount … this
> is additional.

The handoff requires the opposite: *"Price changes trigger temporary MCP re-quote."* The
discount, fuel and greeter questions all currently resolve to local arithmetic and must
instead round-trip through `calculate_temporary_quote_units`.

### 7. Seven of ten fixtures encode the removed path

`access-tca-wedding`, `boston-offsite`, `boston-offsite-options`, `nine-leg-pagination`,
`sixteen-leg-route-map`, `three-city-suv-special-event`, `whistler-iol-invitational`.

**▲ The regression suite is the safety net for this migration and it is built on the
behaviour being removed.** Replacing fixtures is not cleanup at the end — it has to
happen early enough to catch mistakes made during the migration, and it needs captures
from the new MCP to build against. (Q5 below.)

### 8. Flights, comparisons, docs

- Every airport stop needs a timezone-aware `scheduled_time` and `flight_type`.
  Already implemented; the placeholder path stays, and stays disclosed.
- Every comparison option must contain every trip. `generate_quote_options` is already
  used this way — needs an assertion rather than a rewrite.
- `README`, `.claude-plugin/plugin.json` compatibility string, and the mirrored copies in
  `assets/plugin-root/` all still describe the approximate flow and must move together.

## Questions that block the build

These are for Savoya engineering. Each one changes what gets built, so none should be
guessed at.

| # | Question | Why it blocks |
|---|---|---|
| **Q1** | With the approximate path gone, what should a CSM get for a zero-passenger profile or a market with no stored rate? Blocked with an explanation, or is there a supported path? | Determines whether we build an error state or a new flow. Today these produce a usable estimate. |
| **Q2** | Greeter / on-site coordinator fees have no Core concept. If no plugin script may compute a total, does Core price them, or do they stay a non-priced client-facing note? | The greeter question currently adds a real line to a real total. Robyn's Irvine quote used it. |
| **Q3** | Waiving the fuel surcharge on the document: is that a temporary re-quote, or unsupported? | Currently a local waive with a note that the booking needs it applied in Savoya. |
| **Q4** | Is `resolve_vehicle_types` batchable / cacheable per service area, and what is its latency? | It becomes authoritative on every quote; the static table existed to avoid that cost. |
| **Q5** | Can we get captures or a test profile against the new MCP to rebuild fixtures from? | Seven of ten fixtures must be regenerated from real responses, not hand-edited. |
| **Q6** | "Temporary discount must be a whole percentage, total effective ≤ 100%." Is that enforced by Core, or must the plugin validate before calling? | Decides whether we add client-side validation. |
| **Q7** | "Transfer rates need exactly two stops" for temporary pricing. How do out-and-back legs with a mid-stop get a temporary rate? | The 3-hour-gap rule produces exactly this shape routinely. |

## Proposed sequence

Five stages, each independently reviewable and committed separately so the branch reads
as an argument rather than a dump. **Stage 0 gates everything else.**

**Stage 0 — Answers (blocked on Q1–Q7).**
No code. Without Q1 and Q2 we would be guessing at user-visible behaviour.

**Stage 1 — Intake: remove the old path.**
Delete the approximate fallback and `calculate_quote_options` from instructions and code;
make passenger optional; make vehicle metadata come from MCP. Keep the rate-sheet prompt
and disclosed flight placeholders — the handoff explicitly preserves both.
*Gate:* no removed tool name survives anywhere; `regress.py` lint extended to fail on one.

**Stage 2 — Handoff contract v3.**
Carry source tool, raw result, aggregate total, warnings, temporary-pricing provenance,
`persisted: false`. Version the contract so a stale handoff is detected, not
misinterpreted.
*Gate:* an old-shaped handoff is rejected with a clear message.

**Stage 3 — Document flow becomes presentation-only.**
Retire local money math. Route discount / fuel / greeter through
`calculate_temporary_quote_units`. Replace the residual absorption with fail-closed.
*Gate:* no script computes or compounds a total; a mismatch refuses to render.

**Stage 4 — Fixtures and gates.**
Rebuild the seven fixtures from real MCP responses. Add the handoff's acceptance
scenarios: unnamed passenger with eight guests, zero-passenger blocked profile, temporary
hourly with inherited terms, no-stored-rate, combined rate + discount, comparison
completeness.
*Gate:* the full release-gate checklist passes.

**Stage 5 — Docs, version, package.**
README, manifest compatibility, `assets/plugin-root/` mirrors, CHANGELOG. Version 0.23.0.
*Gate:* root docs and mirrors updated in the same commit.

---

## Recommendation on approval

Ship Stage 0 as a conversation with engineering, not a document review. Q1, Q2 and Q3 are
product questions wearing engineering clothes — each one changes what a CSM sees when
something can't be priced, and none of them has an obvious right answer.

Stages 1–2 are safe to start in parallel with those answers, because removing dead tool
references and versioning the handoff are required regardless of how Q1–Q7 land.

**Do not start Stage 3 before Q2 and Q3 are answered.** It is the stage that changes what
CSMs see, and rebuilding it twice is the expensive mistake available here.
