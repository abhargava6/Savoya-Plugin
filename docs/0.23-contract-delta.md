# The new MCP contract — what actually changed

Produced by probing the **live MCP** on 7 October 2026: all nine tool schemas read
directly, plus a real `resolve_vehicle_types` call. This supersedes
`docs/0.23-mcp-migration.md`, which was written from the engineer's handoff PDF and could
only describe what that document claimed.

Three things the PDF did not say change the plan materially. They are marked **★**.

## 1. Money math leaves the plugin

`passenger_count` is now documented as: *"Core uses this with vehicle capacity to choose
the required vehicle quantity and compare full line totals."*

Core decides how many vehicles a group needs and returns the line total. Our plugin
currently multiplies (14 SUVs × $153.99) and compounds percentage adjustments locally.
Both stop.

## 2. Passenger becomes optional — and the cache becomes dead weight

> *"Optional existing passenger id. When omitted, Core deterministically attaches an
> eligible passenger only to the unsaved quote calculation."*

Our `decision-tree.md` node B says take the first result without asking and cache it per
profile. That was correct against the old contract and verified at the time. It is now
wrong: resolve a passenger **only when the user names one**.

Knock-on: `handoff.py passenger`, the `known_clients`/passenger cache in
`~/.savoya-quoting/config.json`, and the "pricing is passenger-independent" note in
`feedback-archive.md` all describe a behaviour that should no longer happen.

## 3. ★ Greeters are vehicle types, not a document line

A live `resolve_vehicle_types` call returns:

```
{"id":12,"name":"Hourly Greeter/Coordinator","capacity":null,"greeter":true, …}
{"id":13,"name":"Single Greet","capacity":null,"greeter":true, …}
```

**This answers the open Q2 from the earlier analysis.** On-site staff is priced by Core as
a quote unit, not invented by us. Today the document flow asks `greeter_cost` and writes
a flat local line — that is exactly the local money math the new contract forbids, and it
is how Robyn's Irvine quote got a hand-entered `$940` "On-site coordinator" line.

Consequence: `greeter_cost` stops being a document-flow question and becomes an **intake**
decision — a quote unit with `vehicle_type_id: 12` or `13`. That is a change to the
decision tree, not a change to the document flow.

## 4. ★ Our static vehicle table is wrong, not just stale

`vehicle-types.md` versus what Core actually returns:

| | |
|---|---|
| **Wrong** | Exec Van capacity: we say "~10", Core says **14** |
| **Missing** | Armored Sedan (15) · Armored SUV (21) · Armored MPV (199) · Premier European Touring (198) · MPV (11) · Hourly Greeter/Coordinator (12) · Single Greet (13) |
| **Fields we never had** | `limited_availability`, `client_can_book`, `classification`, `greeter`, `bus` |

`client_can_book: false` on Mini Bus and Coach Bus is the structured form of something we
discovered by hand ("Mini Bus can't be booked by the client"). It is now a field we can
read instead of a rule we remembered.

Ids and capacities we do have are otherwise correct. The table should become
**terminology and physical dimensions only** — Core owns ids, capacity and eligibility.
Dimensions stay: Core has no concept of them, and they are what rules a coach out of a
venue with a 9×18 ft parking cap.

## 5. Comparisons restructured

`generate_quote_options` now takes an `options` array (**2–5**), each option carrying its
own `key`, `label` and a full `quote_units` list. Every option must contain every trip.
Candidate `vehicle_type_ids` are allowed here — Core prices each and picks the lowest
successful total.

`strategy` is now an enum of five: `value`, `elevated`, `cost_saving`, `quality_focused`,
`custom`. We only know `value` and `elevated`.

## 6. Temporary pricing replaces local adjustments

`calculate_temporary_quote_units` takes, per unit, one `vehicle_type_id` and at least one of:

- **`temporary_rate`** — `rate_type` (`hourly`|`transfer`), `amount` in **cents**, optional
  `label`, `cancellation_hours`, `minimum`. Omitting the last two inherits the ordinary
  quote's terms; supply `cancellation_hours` when no ordinary rate exists.
- **`temporary_discount`** — `basis_points` (500 = 5%), optional `label`. Additive to the
  saved client discount, run through Core's normal discount formula.

Results are never persisted. This is the replacement for the document flow's
`discount_pct` and `fuel` questions, which currently resolve to local arithmetic.

## 7. `requested_stop_count` — a new guard we should send

> *"Total number of itinerary stops requested by the user, including pickup, dropoff, and
> every intermediate stop."*

Not in our plugin at all. It lets Core detect a dropped stop. Given that silently dropping
a stop is exactly the bug class that produced our 0-minute drive times, we should send it
everywhere it is accepted.

## 8. Flights: two new shapes, neither reachable

The flight object now documents three forms:

1. `commercial_tbd: true` + `flight_type` + timezone-aware `scheduled_time` — **what we do today**
2. Known commercial: `flight_type`, `flight_number`, timezone-aware `scheduled_time`, and
   **`airline` as a resolved object with an id**
3. Private: `private: true`, `flight_type`, `scheduled_time`, and **`fbo` as a resolved
   object with an id**

**★ There is no airline resolver and no FBO resolver among the nine tools.** I searched the
full tool list. So forms 2 and 3 are specified but unreachable from the plugin — which
keeps `ENGINEERING.md` B7 open and adds an FBO sibling to it.

## 9. Smaller contract facts

- `query` is explicitly forbidden inside pricing calls (`"query": {"not": {}}`) — stop_ref only.
- Stops: min 2, max 25 per unit. Previews: max 40. Options: max 5. Quote units: max 40.
- `duration` is in **hours** (0.25 / 0.5 / 2), never minutes — unchanged, still worth asserting.
- Pickup can never be `as_directed` — unchanged.

## What is still a question for engineering

The probe answered Q2, Q4 and most of Q6 from the earlier analysis. What remains:

| # | Question |
|---|---|
| **Q1** | With the approximate path gone, what does a CSM see when a quote cannot be priced — no stored rate in the market, or a profile with no eligible passenger? The contract says ask for a temporary rate or pick another vehicle; is that the whole answer? |
| **Q3** | Waiving the fuel surcharge on a client document — is that a `temporary_discount`, or unsupported? Fuel is market-scoped and engine-applied; nothing in the new schema waives it. |
| **Q5** | Can we get a test profile with known rates to rebuild the seven stale fixtures against? |
| **Q7** | Temporary **transfer** rates and multi-stop legs: our 3-hour-gap rule routinely produces out-and-back units with a mid-stop. Does a transfer `temporary_rate` accept those? |
| **Q8 (new)** | Airline and FBO ids are required for known-commercial and private flights, but no tool resolves them. Is a resolver coming, or do these stay out of scope? |
| **Q9 (new)** | What do `cost_saving`, `quality_focused` and `custom` strategies change in Core's selection? We only ever used value/elevated. |

## Plan — documents first, plugin after

Each stage is a reviewable commit on `new-mcp-version-09-24`. No plugin code changes until
Stage D.

### Stage A — Record the contract (no behaviour change)
1. **New** `skills/quote-intake/references/mcp-contract.md` — the nine tools, their
   required arguments, and the removed two. One place the rest of the docs point at,
   instead of tool knowledge scattered through prose.
2. **Rewrite** `vehicle-types.md` — dimensions and terminology only, with an explicit note
   that ids, capacity, `client_can_book` and `limited_availability` come from
   `resolve_vehicle_types`. Fix Exec Van to 14. Add the greeter types.

*Gate:* no document states a vehicle id or capacity as authoritative.

### Stage B — Redraw the decision tree
3. **`decision-tree.md`** — node B becomes "resolve a passenger only if the user named
   one". Node G loses the approximate fallback and gains the temporary-pricing branch.
   A new node covers greeter-as-unit. Nodes for the removed tools go.
4. **`client-questions.md`** — the greeter row moves from "document flow asks for a cost"
   to "intake prices it as a unit".
5. **`questions.md`** — `greeter_cost` leaves the document flow; `discount_pct` and `fuel`
   become MCP re-quotes rather than local lines.

*Gate:* the tree names only tools that exist, and no money is computed outside Core.

### Stage C — Redraw the artifacts
6. The Mermaid flow diagrams published earlier are now wrong in the same places the tree
   was. Regenerate from the updated tree.
7. **`handoff-contract.md`** → v3: source tool, raw result, aggregate total, warnings,
   temporary-pricing provenance, `persisted: false`.
8. **`quote-schema.md`** — copy-and-validate semantics, fail closed on mismatch.
9. **`CLAUDE.md`** — update the rules that reference the old contract.

*Gate:* a reader following the docs alone would build the right thing.

### Stage D — Then the plugin
Scripts, fixtures, version, package — scoped against the documents from Stages A–C rather
than against the PDF. The seven stale fixtures need Q5 answered before they can be rebuilt.

---

**Recommended order of business:** Stage A and B can start immediately — nothing in them
depends on the open questions. Q1 and Q3 block finishing `questions.md` in Stage B, and Q5
blocks Stage D. Q8 and Q9 are worth asking now because they may be cheap for him to answer
and they affect how much of the flight and comparison sections we rewrite.
