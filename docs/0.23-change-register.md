# 0.23 change register

Every change proposed to the plugin for the new MCP contract, one per row, with the
reasoning behind it. **Nothing here is implemented.** This document exists to be reviewed
change by change — approve, defer, reject or amend each one before any code moves.

Sources: live MCP probe 7 Oct 2026 (nine tool schemas + a real `resolve_vehicle_types`
call), `docs/0.23-contract-delta.md`, `GREEN-371`, PRD `R48–R51`, TDD §11.

---

## Correction to the premise

The working assumption has been "MCP + plugin work great, don't break anything." The first
half is no longer true in one specific way, and it changes what "safe" means.

On 22 September the connector served **10** tools. Today it serves **9**:
`plan_approximate_quote_units` and `calculate_quote_options` are gone,
`calculate_temporary_quote_units` is new. Plugin 0.22.0 still routes to both removed tools
— `decision-tree.md` node G falls back to `plan_approximate` when a profile has no
eligible passenger or a market has no stored rate.

So today's plugin works on the happy path and fails on the fallback path, with an
unknown-tool error rather than a graceful message. **Doing nothing is not the no-risk
option.** Group A below exists to close that, and is the only group that is genuinely
urgent.

## How to review this

Each change carries an ID. For each, one of:

- **Approve** — goes into the build queue at the stated sequence position
- **Defer** — correct but not now; it moves to a later release with the reason recorded
- **Reject** — we're not doing it; the reasoning stays here so it isn't re-proposed
- **Amend** — right idea, wrong shape; note what changes

Changes marked **◆ blocked** cannot be finalised until an open question (§7) is answered.
Changes marked **▲ user-flow** touch what a CSM sees and are the ones your pending
feedback most likely affects — those are deliberately grouped so your revisions land in
one place rather than scattered.

## 2. Group A — Latent breakage (urgent)

These close calls to tools that no longer exist. Smallest possible change, no new
behaviour.

### A1 — Remove the approximate-quote fallback
**What** Delete the `plan_approximate_quote_units` branch from node G and every reference.
**Why** The tool is gone from the server. Today a profile with no eligible passenger, or a
market with no stored rate, produces an unknown-tool error instead of a quote or a clear
message.
**Evidence** 12 references across 10 files, including `normalize_quote.py` (branches on
approximate-shaped responses) and `handoff.py` (records it as a source tool).
**Replaces it with** The contract's own answer: *"If an exact quote has no stored rate, ask
the user for a temporary rate or choose a different vehicle."* That is a real CSM-facing
flow, not an error.
**Risk** Low to implement, **user-visible**: a case that produced a labelled estimate now
produces a question.
**Q1 resolved (7 Oct)** The no-eligible-passenger case is no longer ours to pre-empt. We
do not send `passenger_id` at all unless the user named one (B1), so we cannot know in
advance and should not try — Core raises it, the plugin surfaces the warning. **Unblocked.**
**Files** `decision-tree.md`, `quote-intake/SKILL.md`, `handoff.py`, `normalize_quote.py`,
`RULES.md`, `handoff-contract.md`, `evals.json`, `feedback-archive.md`,
`assets/plugin-root/README.md`

### A2 — Remove `calculate_quote_options` references
**What** Delete the tool from instructions and the "never call this" rule that names it.
**Why** Gone from the server. The rule was already "never call it", so this is cleanup, not
behaviour change.
**Risk** Minimal — no live path reaches it.
**Files** `decision-tree.md`, `quote-intake/SKILL.md`, `RULES.md`, `feedback-archive.md`

### A3 — Add a contract-drift guard to the regression suite
**What** A test asserting that no instruction file names a tool outside the current nine.
**Why** This whole group exists because the server changed and nothing told us. The
`instruction paths` lint already proves this kind of guard works; this is the same idea
applied to tool names.
**Risk** None. Pure addition.
**Files** `regress.py`

## 3. Group B — Contract alignment

Changes where the plugin's assumptions and the server's contract have diverged. No new
capability; correctness only.

### B1 — Passenger becomes optional ▲
**What** Resolve a passenger **only when the user names one**. Stop taking the first result,
stop caching per profile.
**Why** The schema now reads: *"Optional existing passenger id. When omitted, Core
deterministically attaches an eligible passenger only to the unsaved quote calculation."*
Our rule — take the first, cache it — was correct against the old contract and is verified
in `feedback-archive.md` ("two passenger ids, byte-identical quotes"). It is now wrong.
**Secondary benefit** Removes a step from every quote and the "I'm using the first
passenger on the profile as a placeholder" disclosure CSMs currently see.
**Knock-on** `handoff.py passenger`, the passenger cache in `~/.savoya-quoting/config.json`,
and the archive note all describe behaviour that should stop.
**Risk** Low. The disclosure disappearing is a visible improvement, not a regression.
**Q1 note (7 Oct)** Confirmed: send nothing rather than "any passenger from cache or Core".
Keeping a cached passenger would preserve the placeholder disclosure for no benefit, and a
zero-eligible-passenger profile surfaces as a Core warning rather than a pre-flight check.
**Files** `decision-tree.md` node B, `quote-intake/SKILL.md`, `handoff.py`,
`feedback-archive.md`

### B2 — Vehicle catalog: Core is the authority
**What** Rewrite `vehicle-types.md` to **dimensions and terminology only**. Ids, capacity,
`client_can_book` and `limited_availability` come from `resolve_vehicle_types`.
**Why** Our static table is not merely stale, it is **wrong**: Exec Van is capacity **14**,
we say "~10". Seven types are missing entirely — MPV (11), Premier European Touring (198),
three armored classes (15, 21, 199), and both greeters (12, 13).
**Why keep dimensions** Core has no concept of physical size. Our length × width figures are
what rule a coach out of a venue with a 9×18 ft parking cap — that rule has no other home.
**Cost** Reverses a deliberate context-budget decision (the table existed to avoid a
per-quote tool call). One extra call per quote, against a wrong answer today.
**Risk** Medium — touches vehicle selection, the highest-consequence part of intake.
**Files** `vehicle-types.md`, `quote-intake/SKILL.md`, `decision-tree.md` node C

### B3 — Send `requested_stop_count`
**What** Include it on every call that accepts it.
**Why** New field: *"Total number of itinerary stops requested by the user, including
pickup, dropoff, and every intermediate stop."* It exists so Core can detect a dropped
stop. Silently dropping a stop is exactly the bug class that gave us 0-minute drive times
in 0.20.0 — this is the server offering to catch it for us.
**Risk** None. Additive.
**Files** `decision-tree.md`, `quote-intake/SKILL.md`, `handoff-contract.md`

### B4 — Comparisons: new `options` structure ▲
**What** `generate_quote_options` now takes an `options` array (**2–5**), each with its own
`key`, `label` and complete `quote_units`. Candidate `vehicle_type_ids` are allowed inside
— Core prices each and picks the lowest successful total.
**Why** The call shape changed. Also an enforced rule we only had as prose: every option
must contain every trip.
**Open** `strategy` is now five values — `value`, `elevated`, `cost_saving`,
`quality_focused`, `custom`. We only use two. ◆ blocked on Q4 for what the other three
change in Core's selection.
**Risk** Medium. This is the path most multi-option quotes take.
**Files** `decision-tree.md` node G, `quote-intake/SKILL.md`

### B5 — `calculate_quote_units` takes one vehicle, never a list
**What** Assert one `vehicle_type_id` per unit.
**Why** *"Each trip requires one vehicle_type_id; candidate lists are not accepted."*
Candidate lists now belong only in `generate_quote_options`.
**Risk** Low — matches what we do already; this makes it explicit so it isn't drifted into.
**Files** `decision-tree.md`, `quote-intake/SKILL.md`

### B6 — Flights: TBD only, with a documented seam
**What** Keep `commercial_tbd: true` + `flight_type` + timezone-aware `scheduled_time` as
the only shape we send. Document the other two forms as **known and deliberately unused**.
**Why** The contract now describes known-commercial flights (needs `airline` as a resolved
object with an id) and private flights (needs `fbo` likewise). **Neither resolver exists
among the nine tools** — I searched the full list. They are specified but unreachable.
**Why document rather than ignore** When the resolvers land, the next person needs to know
the shape was understood and consciously deferred, not missed. The seam names exactly what
has to change and where.
**Risk** None — this is today's behaviour, written down.
**Files** `decision-tree.md`, `quote-intake/SKILL.md`, new `mcp-contract.md`

### B7 — Record the contract in one place
**What** New `skills/quote-intake/references/mcp-contract.md`: the nine tools, required
arguments, limits, and the two removed ones with the date.
**Why** Tool knowledge is currently scattered through prose in four files, which is how it
drifted without anyone noticing. One file makes the next contract change a diff.
**Risk** None. A3's guard reads this file, so it also becomes testable.
**Files** new file; `decision-tree.md` and both SKILL.md point at it

## 4. Group C — Money ownership ▲

The biggest behavioural group. All of it moves money out of the plugin.
**Every change here is user-visible**, and this is the section your pending workflow
feedback most likely touches.

### C1 — `discount_pct` becomes a Core re-quote
**What** The document flow's discount question calls `calculate_temporary_quote_units` with
`temporary_discount.basis_points` instead of adding a local percentage line.
**Why** `questions.md:15` currently says, in writing, *"Do not re-quote through the
engine."* The contract requires precisely that. A discount applied locally is our
arithmetic on Core's number; a discount applied through Core is Core's number.
**Detail** `basis_points` — 500 = 5%. Additive to the saved client discount, run through
Core's normal discount formula. Whole percentages only.
**Risk** High. Changes a number on a client document, and the document flow now makes an
MCP call where it previously did arithmetic.
**Files** `questions.md`, `quote-document/SKILL.md`, `apply_adjustments.py`

### C2 — Retire local money math
**What** Strip `apply_adjustments.py` to presentation-only. `recompute()` (percentage
compounding in list order) goes.
**Why** Release gate: *no plugin script calculates or compounds a final monetary total.*
`recompute()` is that function.
**Q2 resolved (7 Oct)** Fuel adjustment is dropped entirely (C3), so nothing in this
script needs to survive for it. **Unblocked.**
**Risk** High. This script is the document-level pricing layer: discount, fuel, greeter,
waivers all route through it.
**Files** `apply_adjustments.py`, `questions.md`, `quote-document/SKILL.md`

### C3 — Drop fuel-surcharge adjustment entirely
**Decided 7 Oct: drop the capability.** Fuel comes from Core and is presented as Core
applied it. No waive, no add, no local line.
**Why** Fuel is market-scoped and engine-applied, and nothing in the new schema subtracts
it — `temporary_discount` is additive and a surcharge is not a discount. The alternatives
were an offsetting discount (right arithmetic, wrong semantics: it would print on the
client's document as a *discount*) or a documented local exception that keeps exactly the
hand-arithmetic this release removes. Neither earns its risk.
**Consequence — the document flow loses a question.** `fuel` leaves the sequence: seven
questions become six. The `[if:fuel_surcharge]` terms bullet stays, since it reflects what
Core actually applied, and `verify_document.py`'s market-aware percentage check stays with it.
**What a CSM loses** Showing a client a waived surcharge. They would now get it waived in
Savoya first — arguably where it always belonged, since today's waive already carries a
note that the booking needs the waiver applied there anyway.
**Risk** Low now that it is a removal rather than a redesign.
**Files** `questions.md`, `decide.py`, `apply_adjustments.py`, `quote-document/SKILL.md`

### C4 — Fail closed instead of absorbing the residual
**What** Delete `apply_adjustments.py:117–125`, which absorbs penny-level drift into the
last engine-sourced line. Replace with a hard failure.
**Why** The contract: *"If normalized data and the raw MCP result disagree, fail closed. Do
not repair the difference with arithmetic."* This code is literally that repair.
**Risk** **Visible regression, deliberately.** Quotes that render fine today will start
refusing to render when reconstruction drifts by a cent. That is correct and it will look
like a bug to a CSM unless the message explains itself. Needs a message worth reading.
**Files** `apply_adjustments.py`, `verify_document.py`

### C5 — `normalize_quote.py` copies, never rebuilds
**What** Copy Core's `pricing_summary.total_amount`, `line_total`, `aggregate_total`,
quantity, minimum, cancellation and warnings. Validate; never reconstruct.
**Why** Core now decides vehicle quantity from `passenger_count` and capacity. Any local
reconstruction is a second opinion that can disagree.
**Risk** Medium.
**Files** `normalize_quote.py`, `quote-schema.md`

## 5. Group D — Greeters as a priced unit ▲

### D1 — Greeter rate check, then route by who asked
**What** Greeters are Core vehicle types: **id 12 "Hourly Greeter/Coordinator"**, **id 13
"Single Greet"**, both `greeter: true`, capacity `null`. The rule:

| Who raised it | Greeter rate in that market? | Where it's handled |
|---|---|---|
| **Client asked** | Yes | **Intake** — priced as a Core quote unit |
| **Client asked** | No | **Document flow** — ask the user for a cost |
| **User wants it**, client didn't ask | Yes | **Document flow**, using the Core rate |
| **User wants it**, client didn't ask | No | **Document flow**, ask the user to supply |

**Why this shape** The rate check is the constant — never ask a human for a number Core can
give. The *location* follows who raised it: something the client asked for is part of the
quote they requested, so it belongs in intake; something the CSM adds is an add-on to a
finished quote, so it belongs in the document flow.
**Why it matters** Robyn's Irvine quote carried a hand-entered `$940` "On-site coordinator"
line. Core may have had a rate for it. We will not know until the check exists.
**New requirement** Both skills need a market greeter-rate lookup — `preview_rates` scoped
to vehicle type 12/13.
**Risk** Medium–high. New branch in intake, and `greeter_cost` changes meaning in the
document flow from "supply a number" to "confirm Core's rate, or supply one".
**Files** `decision-tree.md` (new node), `client-questions.md`, `questions.md`,
`decide.py`, `quote-document/SKILL.md`

## 6. Group E — GREEN-371 forward-compatibility

Ethan is building cross-market sourcing now (In Progress, assigned, acceptance criteria
settled). It will change `quote.json`. The decision is to **shape the seam, build nothing**.

### E1 — Give `quote.json` room for multiple pricing sources
**What** Document — not implement — that a leg's pricing will become an array of sources,
each carrying its own service area, rate, quoted/billable time, cancellation policy,
minimum and excess drive time. TDD §11.3's proposed shape:
`sources: [{service_area, vehicle_type, quantity, rate, quoted_time, billable_time,
cancellation_policy, minimum, excess_drive_time}]`.
**Why now** Every renderer currently assumes **one rate, cancellation policy and minimum per
vehicle type per leg**. R51 breaks exactly that assumption. Writing the schema so a second
source can be added is nearly free now and a rewrite later.
**Why not build it** TDD §11.3 says the shape is *"not yet confirmed, pending Core's actual
response contract"*, and GREEN-371 itself asks Ethan to propose it. Building against a
guess is how we'd end up migrating twice.
**Risk** None now. Avoids a large risk later.
**Files** `quote-schema.md` (documented as forward-looking), TDD §11.3 cross-reference

### E2 — Placeholder node in the decision tree
**What** A named, explicitly-not-built node where the cross-market lookup will sit: after
rate discovery shows the primary market can't cover demand, user-initiated only.
**Why** R48 is user-initiated in this phase — the product does not detect insufficient
inventory and prompt. Recording where it goes keeps the surrounding nodes from being drawn
in a way that has no room for it.
**Risk** None.
**Files** `decision-tree.md`

### E3 — Don't harden the single-rate assumption
**What** A constraint on Groups B and C: while touching `normalize_quote.py`,
`render_print.py` and `verify_document.py`, do not add new logic that assumes one rate per
vehicle type per leg.
**Why** TDD §11.2 names these exact files as what R51 breaks. Fixing them for 0.23 in a way
that deepens the assumption means undoing it in 0.24.
**Risk** None — it's a review criterion, not code.

## 8. Fixture and test coverage plan

Today's suite is the only safety net for all of the above, and it is not currently fit for
it: seven of ten fixtures were built on the removed approximate path, and three of those
fail outright under the new contract's validation.

**Decision taken:** rebuild all ten from live MCP responses. The three survivors were
authored against the old contract too — they pass by luck rather than by being right.

### Phase 1 — Triage and freeze (before any code change)
Record what each fixture currently proves, so coverage is replaced rather than lost. Tag
each as: still-valid shape / removed-path / needs-new-capture. Freeze today's suite output
as the "before" baseline.

### Phase 2 — Capture ◆
Run each scenario against the live MCP and keep the raw responses. **◆ blocked on Q3** — a
test profile with known rates across the markets we need, including one with greeter rates
and one without, which D1 cannot be tested without.

### Phase 3 — Scenario matrix
Coverage target, with why each earns its place:

| Scenario | Proves |
|---|---|
| Ordinary exact quote, named passenger | Baseline |
| Ordinary exact quote, **no** passenger named | B1 — Core attaches |
| Group larger than one vehicle | Core's capacity-aware quantity, not our multiplication |
| Multi-trip, mixed vehicle types | Aggregate totals |
| Comparison, 2 options, every trip in each | B4 |
| Comparison, 5 options | B4's new upper bound |
| Temporary **rate**, no stored rate in market | A1's replacement path |
| Temporary **discount** | C1 |
| Temporary rate **and** discount combined | Interaction |
| Greeter, client asked, rate present | D1 row 1 |
| Greeter, client asked, **no** rate | D1 row 2 |
| Greeter, user-initiated, rate present | D1 row 3 |
| Blocked: no eligible passenger | Q1's answer, once decided |
| Airport stop, commercial TBD | B6 |
| 16-leg route map, 9-leg pagination, heavy notes | Existing rendering coverage, preserved |
| Fail-closed: deliberately mismatched totals | C4 refuses to render |

### Phase 4 — Guards
Keep all five existing guards (instruction paths, route, client_notes, question gating,
plus A3's new contract-drift check). **Each new guard gets broken on purpose first** — the
map stub was for months a flat fill in exactly the colour a failed tile fetch produces,
which is why the suite could never have caught a blank map.

### Phase 5 — Gate
`regress.py --pdf` green across the full matrix before any `.plugin` is built. The suite
never points at a reduced fixture set — a green `1/1` is worse than a red `3/10` because it
looks like success.
